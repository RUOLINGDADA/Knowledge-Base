# 工程技术知识库

面向嵌入式、机器人与自主移动小车开发的 Markdown 知识库模板。

这套方法适合记录 RM 备赛、STM32、ROS、树莓派、传感器、运动控制和机械调试过程。它不追求收集大量资料，而是把一次调试、一次学习和一段代码沉淀成下一次可以复用的工程经验。

> 核心方法：**问题现象 → 定位过程 → 解决方案 → 踩坑记录 → 原理解释**

## 快速开始

### 方式一：直接使用 Markdown

1. 将本仓库克隆到本地，或直接下载 ZIP。
2. 按模块建立文件夹和 Markdown 文件。
3. 每次遇到问题、学完知识点或完成一个功能后，使用对应模板记录。
4. 将代码完整实现保存在项目仓库，知识库只保留关键片段、参数和踩坑信息。
5. 通过 Git 提交笔记，保留每次修改记录。

```bash
git clone https://github.com/<your-name>/<your-repository>.git
cd <your-repository>
```

### 方式二：配合 Cherry Studio 使用

1. 打开 Cherry Studio，创建一个自定义助手。
2. 将本文的[工程笔记助手提示词](#工程笔记助手提示词)复制到系统提示词栏。
3. 用自然语言描述调试过程、学习内容或代码功能。
4. 检查助手生成的分类、层级、标签和技术细节。
5. 将确认后的内容保存为 Markdown，归档到对应模块目录。

## 推荐目录结构

目录可以按个人项目调整，建议保持模块名称稳定，方便长期检索。

```text
Knowledge-Base/
├── README.md
├── 00_每日笔记/       # 临时记录，定期整理
├── 01_原理理解/       # 操作系统、通信、控制、计算机基础
├── 02_底层电控/       # STM32、驱动、电机、传感器、通信
├── 03_上层系统/       # ROS、导航、定位、感知、任务逻辑
├── 04_机械硬件/       # 结构、装配、线束、加工和可靠性
└── 05_资料速查/       # 命令、接口、数据手册和常用参数
```

### 文件命名建议

使用“主题 + 场景”的方式命名，避免只使用日期或模糊名称。

```text
串口通信_波特率不一致导致乱码.md
ROS2_节点与话题.md
STM32_定时器输出PWM.md
树莓派_串口权限配置.md
```

## 三层知识分级

| 层级 | 判断标准 | 记录重点 | 复习目标 |
| --- | --- | --- | --- |
| **精通层** | 能独立实现、调试并解释原因 | 完整排查链路、关键参数、可复现方案 | 遮住答案后复现解决过程 |
| **理解层** | 能说明工作流程，但还不能稳定落地 | 核心逻辑、接口关系、常见误区 | 用自己的话讲清楚原理 |
| **了解层** | 知道用途和查找方向，尚未深入实践 | 一句话定义、关键词、可靠资料入口 | 知道何时使用、去哪里查 |

层级不是永久标签。完成一次真实项目验证后，可以把笔记从“了解层”升级为“理解层”或“精通层”。

## 笔记类型

### 1. 问题排查型

适合记录 Bug、硬件异常、环境配置问题和调试过程。

```markdown
# [模块分类] 问题主题

> **分类**：底层电控 / 上层系统 / 原理理解 / 资料速查 / 机械硬件
> **层级**：精通层 / 理解层 / 了解层
> **标签**：#技术栈 #模块 #关键词 #层级

## 问题现象

描述触发条件、实际表现和预期结果之间的差异。

## 排查过程

1. 检查了什么，以及观察到什么现象。
2. 根据现象缩小到哪个模块。
3. 最终确认的直接原因。

## 最终解决方案

- 写出可以重新执行的解决步骤。
- 记录需要保持一致的配置、接线或版本。

## 核心代码 / 配置片段

只保留最关键的 3～5 行，并标注修改点。

## 踩坑记录

- 为什么会出现这个问题，新手容易忽略什么。
- 同类问题如何快速判断。

## 底层原理点睛

用 1～2 句话说明硬件、驱动或系统为什么会产生这个现象。
```

### 2. 知识学习型

适合记录一个协议、组件、算法或系统概念。

```markdown
# [模块分类] 知识主题

> **分类**：原理理解
> **层级**：理解层
> **标签**：#技术栈 #知识点 #核心概念 #理解层

## 核心定义

用自己的话说明它是什么、解决什么工程问题。

## 核心逻辑 / 工作流程

1. 输入是什么。
2. 系统按什么顺序处理。
3. 输出是什么，哪些模块会使用输出。

## 关键参数 / 指标

| 参数 | 影响 |
| --- | --- |
| 参数一 | 参数改变后会出现什么实际现象 |
| 参数二 | 如何选择或验证 |

## 常见误区

记录容易混淆的概念、边界条件和使用限制。

## 底层原理点睛

用 1～2 句话讲清本质，并联系实际工程现象。
```

### 3. 代码功能型

适合记录已经实现的驱动、工具脚本或功能模块。

```markdown
# [模块分类] 功能主题

> **分类**：底层电控 / 上层系统
> **层级**：精通层 / 理解层
> **标签**：#编程语言 #功能模块 #层级

## 功能描述

说明功能、输入、输出和使用场景。

## 核心逻辑

1. 接收或读取输入。
2. 校验、转换并处理数据。
3. 调用硬件或系统接口。
4. 返回结果并处理异常。

## 关键代码片段

只保留最能体现核心逻辑的 3～5 行代码，并写必要注释。

## 踩坑记录

- 编写或调试时遇到的问题。
- 环境依赖、权限、版本兼容和边界条件。

## 底层原理点睛

说明代码如何与操作系统、驱动、总线或硬件交互。
```

## 标签规范

标签用于跨目录检索，命名应稳定、简短、可复用。

- 技术栈统一使用小写：`#python`、`#ros`、`#ros2`、`#stm32`、`#linux`。
- 模块名称保持统一：`#串口通信`、`#激光雷达`、`#电机控制`。
- 层级固定为：`#精通层`、`#理解层`、`#了解层`。
- 同一概念只保留一个主要写法，例如统一使用 `#串口通信`，不要交替使用 `#串口`、`#串口通讯`。
- 一篇笔记建议保留 3～6 个标签，避免标签泛滥。

示例：

```text
#stm32 #串口通信 #乱码排查 #精通层
#ros2 #节点 #话题通信 #理解层
#python #键盘控制 #小车 #精通层
```

## 记录工作流

1. **先记原始现象**：记录触发条件、日志、波形、错误码和预期行为。
2. **再记有效定位**：保留真正缩小范围的检查步骤，不堆砌无效尝试。
3. **明确可复现方案**：写清接线、版本、命令、参数和关键代码。
4. **补充踩坑记录**：把容易再次发生的错误单独写出来。
5. **补上原理解释**：用工程现象说明底层逻辑，避免只记“改了什么”。
6. **归档与复盘**：临时内容放入 `00_每日笔记`，每周整理到正式模块。
7. **升级层级**：经过实机验证或独立复现后，再调整知识层级。

## 工程笔记助手提示词

将下面内容粘贴到 Cherry Studio 自定义助手的系统提示词栏，即可让助手按本知识库规范整理输入内容。

```text
你是嵌入式与机器人工程笔记助手，服务于 RM 备赛和自主移动机器人开发。请把用户输入的调试过程、学习内容或代码功能，整理成可检索、可复现的 Markdown 工程笔记。

要求：
1. 自动判断内容属于问题排查型、知识学习型或代码功能型。
2. 自动判断层级：精通层、理解层或了解层。精通层重实操，理解层重逻辑，了解层重索引；不要夸大层级。
3. 分类只能使用：底层电控、上层系统、原理理解、资料速查、机械硬件。
4. 技术栈标签使用小写，例如 #python、#ros、#stm32；模块和层级标签保持统一。
5. 所有原理必须联系硬件、代码或实际现象解释。
6. 必须记录踩坑点、环境依赖、版本差异、权限问题和反直觉参数。
7. 代码只保留最核心的 3～5 行，不输出冗长的完整代码。
8. 输出标准 Markdown，不写客套话、总结或无关拓展。
9. 标题统一为“[模块分类] 笔记主题”。

问题排查型必须包含：
问题现象、排查过程、最终解决方案、核心代码/配置片段、踩坑记录、底层原理点睛。

知识学习型必须包含：
核心定义、核心逻辑/工作流程、关键参数/指标、常见误区、底层原理点睛。

代码功能型必须包含：
功能描述、核心逻辑、关键代码片段、踩坑记录、底层原理点睛。

当用户信息不足时，基于已知内容整理，不虚构测试结果；无法确定的内容明确标记为“待验证”。
```

## 示例输入

### 串口乱码排查

```text
今天用 pyserial 写树莓派和 STM32 的串口通信，发送的数据全是乱码。后来发现树莓派波特率是 9600，STM32 是 115200，改成一致后恢复正常。最开始运行还提示没有权限，确认是用户不在 dialout 组，加入用户组后解决。
```

适合归档到 `02_底层电控/串口通信/`，标签可使用：

```text
#python #stm32 #linux #串口通信 #精通层
```

### ROS 通信概念

```text
今天学习 ROS 2 的节点和话题。节点是独立运行的程序，话题是节点之间传递消息的通道，发布者发送消息，订阅者接收消息，并且一个发布者可以对应多个订阅者。
```

适合归档到 `03_上层系统/ros2/`，标签可使用：

```text
#ros2 #节点 #话题通信 #理解层
```

### 键盘控制小车

```text
写了一个 Python 键盘控制小车的脚本，使用 pyserial 发送指令。W 前进、S 后退、A 左转、D 右转、空格停止，每个按键对应一个十六进制指令帧。
```

适合归档到 `03_上层系统/控制脚本/`，标签可使用：

```text
#python #pyserial #键盘控制 #小车 #精通层
```

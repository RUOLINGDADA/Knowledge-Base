# [技术/网络与嵌入式] 树莓派未成功连接时反复取消并重新启用 Windows 共享

## 问题现象

笔记本通过 WLAN 上网，再用网线连接树莓派，并在 Windows 上启用 Internet Connection Sharing（ICS）。有时共享已经勾选，但树莓派没有成功获得地址或无法访问网络；在笔记本上多次执行“取消共享 → 应用 → 再次启用共享 → 应用”后，连接可能恢复。

需要区分两个结果：

- **树莓派能否与笔记本局域网互通**：主要依赖物理链路、网卡状态、IPv4 地址和 DHCP。
- **树莓派能否访问互联网**：还依赖 ICS 的 NAT、转发、DNS 和 Windows 防火墙。

反复切换共享有时能恢复状态，但它本身不能证明问题一定在树莓派；也不能替代对接口、地址和路由的检查。

## 可能发生了什么

重新启用 ICS 时，Windows 可能重新绑定上游 WLAN 与下游物理以太网，并重新配置下游接口的私有地址、DHCP 和 NAT。常见默认下游地址是 `192.168.137.1/24`，但现场应以 `ipconfig` 的实际输出为准。

如果之前共享到了错误的虚拟网卡、网桥没有解除、以太网接口仍保留旧的静态地址，或者 ICS 服务状态没有及时刷新，树莓派就可能拿不到 DHCP 地址。取消后重新启用共享，相当于触发了一次配置重建，因此偶尔会表现为“多试几次才成功”。

## 推荐处理顺序

### 1. 先确认硬件链路和接口角色

1. 确认网线支持数据传输，树莓派已上电，笔记本的物理以太网接口显示为“已连接/启用”。
2. 打开 `ncpa.cpl`，确认 WLAN 和物理以太网是两个独立连接。
3. 如果 WLAN 或以太网显示“桥接的”，先检查是否存在“网桥”；本场景优先使用 ICS，不要让 WLAN 成为网桥成员。
4. 在 WLAN 属性的“共享”选项卡中，家庭网络连接选择连接树莓派的物理“以太网”，不要选择 `vEthernet`、WSL、Tailscale 或其他虚拟适配器。

### 2. 只进行一次完整的取消/重启共享

不要连续快速点击。按下面顺序完成一次，让 Windows 有时间重建配置：

1. 取消 WLAN 的“允许其他网络用户通过此计算机的 Internet 连接来连接”。
2. 点击“应用”，等待以太网状态刷新。
3. 检查以太网 IPv4 是否恢复为自动获取；必要时在 IPv4 属性中选择自动获取 IP 和 DNS。
4. 再次打开共享，勾选允许共享。
5. 选择连接树莓派的物理以太网，点击“应用”。
6. 等待约几十秒，再开始查询地址和测试连通性。

重复切换超过一两次仍未恢复时，应停止继续点击，转入分段排查。频繁切换可能让地址、路由和虚拟适配器状态更难判断。

### 3. 在 Windows 验证 ICS 是否真的生效

```powershell
ipconfig
Get-NetAdapter
Get-NetIPConfiguration
Get-NetRoute -AddressFamily IPv4
Get-NetNeighbor -AddressFamily IPv4
```

重点观察：

| 检查项 | 正常方向 | 异常时优先怀疑 |
| --- | --- | --- |
| 物理以太网状态 | `Up`/已连接 | 网线、端口、驱动或接口被禁用 |
| 以太网 IPv4 | 通常为 `192.168.137.1`，以实际输出为准 | ICS 未绑定、旧静态地址、共享到了错误接口 |
| 树莓派邻居项 | 能看到树莓派 IP/MAC | 二层链路、树莓派未配置地址或 ARP 未响应 |
| 默认路由 | WLAN 仍承担上游默认路由 | WLAN 断开、网桥或 VPN 改写路由 |

### 4. 在树莓派分段测试

```bash
ip -br addr
ip route
ip neigh
ping -c 4 192.168.137.1
ping -c 4 8.8.8.8
ping -c 4 www.baidu.com
```

判断顺序：

| 结果 | 结论 |
| --- | --- |
| 没有有线接口地址 | 树莓派未拿到 DHCP 地址，先查接口、网线和 ICS 下游配置 |
| 能 ping `192.168.137.1` | 笔记本与树莓派的局域网链路基本正常 |
| 网关能通但 `8.8.8.8` 不通 | ICS/NAT、Windows 防火墙、VPN 或上游 WLAN 有问题 |
| 公共 IP 能通但域名不通 | DNS 配置或 DNS 转发有问题 |

如果树莓派使用 NetworkManager，可查看并重新连接有线接口：

```bash
nmcli device status
nmcli connection show
```

`nmcli` 不存在或系统由其他网络服务管理时，不要把命令不存在误判为网卡故障；应使用该系统实际的网络管理工具。

若反复切换后 DHCP 仍不稳定，可跳过 DHCP 直接给树莓派配置静态 IP，见下文。

## 给树莓派配置静态 IP（绕过 DHCP 不稳定）

反复切换共享仍不稳定时，可跳过 ICS 的 DHCP，直接给树莓派配固定 IP。Windows ICS 的共享网段固定为 `192.168.137.0/24`，静态配置必须与它一致；填写前先用 `ipconfig` 确认 Windows 以太网口确实是 `192.168.137.1`。

以 NetworkManager 的 `nmtui` 为例：

```bash
nmtui
```

选择 `Edit a connection` → 有线连接 → `Edit` → `IPv4 CONFIGURATION` 改为 `Manual` 并展开：

1. `Addresses` 点击 `Add`，按下表依次填入。
2. `DNS servers` 填入 `223.5.5.5, 8.8.8.8`。
3. 勾选 `Require IPv4 addressing for this connection to complete`，避免 IPv6 优先导致网络异常。
4. `OK` 保存后，回到 `Activate a connection` 重新激活该连接。

### 填写参数（Windows 共享网络场景）

| 项 | 值 | 说明 |
| --- | --- | --- |
| Address | `192.168.137.2` | 树莓派自己的固定 IP，必须落在 ICS 网段内；避开网关 `.1`，取 `.2`～`.254` 均可 |
| Netmask | `255.255.255.0` | 子网掩码，等价于 `/24`：前 24 位是网络位、后 8 位是主机位，决定哪些地址算"同一局域网" |
| Gateway | `192.168.137.1` | 默认网关，即 Windows 笔记本以太网口（ICS 主机）地址；树莓派发往其他网段和互联网的数据包都交给它 |
| DNS servers | `223.5.5.5, 8.8.8.8` | 域名解析服务器：`223.5.5.5` 为阿里公共 DNS，`8.8.8.8` 为谷歌公共 DNS，用作备用 |

各参数含义：

- **Address（IP 地址）**：设备在本网络中的唯一标识；配错网段会导致与网关互相"看不到"。
- **Netmask（子网掩码）**：划分网络位与主机位；两端掩码不一致时无法通信。
- **Gateway（默认网关）**：通往其他网络的出口，必须填 ICS 主机的以太网地址 `192.168.137.1`。
- **DNS servers（域名服务器）**：把 `www.baidu.com` 这类域名解析成 IP；留空或填错会出现"能 ping 通 IP、打不开域名"。

保存后验证：

```bash
ip -br addr
ping -c 4 192.168.137.1
ping -c 4 8.8.8.8
ping -c 4 www.baidu.com
```

旧版 Raspberry Pi OS（dhcpcd）等价做法是编辑 `/etc/dhcpcd.conf`：

```bash
interface eth0
static ip_address=192.168.137.2/24
static routers=192.168.137.1
static domain_name_servers=223.5.5.5 8.8.8.8
```

静态 IP 只绕开 DHCP，不修复 ICS 转发；配好后若仍不通公网，问题在 Windows 端 ICS/NAT 或防火墙。

## 仍未恢复时的进一步动作

- 在 Windows“网络连接”中禁用再启用**物理以太网**，再按一次完整的 ICS 取消/启用流程。
- 检查 `SharedAccess`（Internet Connection Sharing）服务是否运行；修改服务前记录当前状态，避免把服务问题与网线问题混在一起。
- 临时断开 VPN、Hyper-V/WSL 虚拟交换机和其他会改写路由的网络软件，完成基础链路验证后再逐项恢复。
- 在树莓派上确认有线接口名可能是 `eth0` 或 `end0`，不要在脚本中写死接口名。
- 若笔记本每次重启后都需要反复切换共享，记录 `ipconfig /all`、`Get-NetAdapter`、树莓派 `ip addr` 和 `ip route` 输出，进一步定位是 DHCP、服务、驱动还是拓扑问题。

## 踩坑记录

- “共享已勾选”不等于树莓派已经拿到地址；必须同时检查以太网地址、树莓派地址、默认路由和分段 ping 结果。
- 反复取消/启用共享可能暂时恢复 ICS 配置，但属于状态刷新手段，不是确定的根因修复。
- “家庭网络连接”指 ICS 的下游接口，不是家里的 Wi-Fi 名称。
- 如果存在网桥，应先确认是否有虚拟机等依赖；删除或解除网桥可能暂时影响这些虚拟网络。
- `192.168.137.1` 是常见默认值，不应在没有查看 `ipconfig` 前直接把它当成必然地址。
- 静态 IP 只是绕开 ICS 的 DHCP，不代表 ICS/NAT 转发正常；配好后仍要分段 ping 验证。

## 原理 / 因果点睛

Windows ICS 同时承担下游地址配置、DHCP、NAT 和 DNS 转发。取消并重新启用共享会触发这些组件重新绑定和初始化，所以可能暂时恢复树莓派连接；如果底层链路、网桥、虚拟适配器或服务状态仍有问题，重复切换只会掩盖而不会消除根因。

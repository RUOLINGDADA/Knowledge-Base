# [技术/网络与嵌入式] Windows ICS 与网络桥接：原理和地址

## 核心定义

### Internet Connection Sharing（ICS）

ICS 是 Windows 的连接共享功能。它把一块能访问互联网的上游接口共享给另一块下游接口，通常包含：

- 在下游接口提供一个私有 IPv4 网段。
- 为下游设备提供 DHCP 地址、网关和 DNS 信息。
- 对下游到上游的流量做 NAT，使树莓派使用 Windows 的上游连接访问互联网。

### 网络桥接（Network Bridge）

网桥把多个接口放进同一个二层广播域，类似软件交换机。终端通常直接从上游网络获得地址，流量不经过 ICS 的 NAT/DHCP 逻辑。

## 为什么删除网桥后才看到“共享”选项卡

这是接口角色冲突造成的 Windows 配置限制：

1. WLAN 加入网桥后，物理 WLAN 由“网桥”这个逻辑接口统一承载。
2. ICS 需要选择明确的上游和下游接口，并在下游接口上配置私有地址和 DHCP/NAT。
3. 网桥成员接口不能再被 ICS 当成独立的共享接口管理，因此 WLAN 属性页通常不显示“共享”选项卡。

删除网桥只是让 WLAN、以太网恢复为独立接口，从而恢复 ICS 的配置入口。它不是所有网络共享方案的必需步骤；如果使用独立路由器、另一块网卡或专门的虚拟路由配置，就不必采用这个操作。

## 为什么“家庭网络连接”选择以太网

ICS 的界面把“家庭网络连接”定义为共享给其他设备的下游接口：

| 接口 | 本场景角色 | 是否选择 |
| --- | --- | --- |
| WLAN | 上游，连接互联网 | 在此打开“共享” |
| 物理以太网 | 下游，网线连接树莓派 | 选择为“家庭网络连接” |
| `vEthernet`/WSL | 虚拟网络，除非专门设计路径 | 通常不选 |
| Tailscale | VPN/覆盖网络 | 通常不选 |

选择错误会导致 ICS 把地址、DHCP 或 NAT 绑定到虚拟网卡，树莓派虽然插着网线，却拿不到正确网关。

## 为什么主机通常是 `192.168.137.1`

`192.168.137.1` 不是 SSH、以太网或 IPv4 协议规定的固定地址，而是 Windows ICS 的默认实现约定：

- `192.168.137.0/24` 是共享下游常用的私有网段。
- Windows 把下游接口设为 `192.168.137.1`，作为树莓派的默认网关。
- DHCP 通常从同一网段分配 `192.168.137.x` 给树莓派。

因此“为什么一定是”应改成“为什么通常是”：不同 Windows 版本、策略、已有地址冲突、第三方网络软件或手工配置可能使实际结果不同。配置完成后始终用 `ipconfig` 查询，不要无条件把树莓派静态写成 `192.168.137.2`。

## 地址关系示例

| 设备/接口 | 示例地址 | 作用 |
| --- | --- | --- |
| Windows WLAN | 由路由器分配，如 `192.168.1.23` | 上游互联网连接 |
| Windows 以太网 | `192.168.137.1/24` | ICS 下游网关/NAT 入口 |
| 树莓派以太网 | `192.168.137.20/24` | SSH 目标和下游客户端 |
| 树莓派默认路由 | `via 192.168.137.1` | 把外网流量交给 Windows |

SSH 连接树莓派时只需要 `192.168.137.20` 这条局域网路径；树莓派访问互联网时才需要默认路由、NAT 和 DNS。

## 常见误区

- **桥接等于共享**：不等于。桥接扩展二层网络，ICS 提供三层私网、NAT 和 DHCP。
- **“家庭网络连接”选上网的 WLAN**：通常错误；它应是给树莓派的下游接口。
- **地址固定为 192.168.137.1**：这是默认值，不是协议常数；实际以命令输出为准。
- **SSH 失败说明树莓派没联网**：不一定。SSH 只要求局域网可达，互联网故障和 SSH 服务故障可以独立存在。
- **有多个以太网图标就随便选**：应按网卡名称和网线实际插入的接口确认，特别注意 Hyper-V、WSL、Tailscale。

## 原理 / 因果点睛

桥接把接口放入同一个二层网络，ICS 则在 Windows 上建立一个受控的私有三层网络。Windows 为 ICS 选择默认下游网段并把自己设为网关，因此 `192.168.137.1` 是实现约定，不是通信的绝对要求。
